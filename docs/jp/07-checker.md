# 07. Checker の役割

## 文書が本体

このプロジェクトの本体は Message Orientated Design の設計原則を記述する文書です。

Checker は、その原則に沿っているかを確認するための付属ツールです。Checker の実装都合によって設計原則を決めるのではなく、文書で定義した原則を Checker が追いかけます。

## 現時点で確認したい項目

Checker では、少なくとも次のような点を検査対象として検討します。

- オブジェクト境界を越えて他オブジェクトの内部関数を直接呼んでいないか。
- 他オブジェクトや他領域の内部状態を直接読み書きしていないか。
- 外部との通信が Message Sender / Message Receptor を経由しているか。
- Receptor にドメイン判断や妥当性判定を入れていないか。
- 受信したメッセージを、Receptor が対応する内部 request 関数へ変換しているか。
- オブジェクト境界を越える結果を return 値だけで返していないか。
- 必要な応答を Sender からメッセージとして返しているか。
- Message Manager に配送以外のドメインロジックを集中させていないか。
- 他領域の情報が必要なとき、その領域へメッセージで問い合わせているか。
- ローカルで完結できる通信を不必要に Global Manager へ集約していないか。

## 継承の扱い

継承の有無だけで合否を決めません。

継承は本設計の中心ではなく、メッセージによる独立性を壊す実装依存を生んでいないかという観点で見ます。

## 未決定事項

Checker の対象言語、静的解析方式、ルールの重大度、設定ファイル形式、CI 連携などはまだ決定していません。
